One pipeline, end to end

From an empty project to a ranked answer. Every output below is what the code printed when it ran, not a sketch of what it would print.

01

Add the package

moon add moonbitstack/moonrag
import {
  "moonbitstack/moonrag",           // documents, contracts, memory store, retrieval
  "moonbitstack/moonrag/split",     // recursive, token, Markdown and HTML splitters
  "moonbitstack/moonrag/load",      // text, CSV, JSON, Markdown, HTML loaders
  "moonbitstack/moonrag/index",     // incremental indexing
}

A loader, a splitter, an embedder and a store are the four pieces a pipeline is assembled from. moonbitlang/async is a dependency of anything that awaits a store or an embedder, so add it too if your project does not have it.

02

The first pipeline

Load a CSV, split it, index it, and ask a question. The indexer is what makes the second run cheap; it is covered in step five. 

async fn ingest(embedder : &@moonrag.Embedder, csv : String) -> Array[@moonrag.Scored] raise {
  let store = @moonrag.InMemoryVectorStore::new(embedder)
  let indexer = @index.Indexer::new(store)

  let documents = @moonrag.Loader::load(@load.CsvLoader::new("people.csv", csv))
  let splitter = @split.RecursiveSplitter::new(chunk_size=500, chunk_overlap=50)
  let pieces : Array[@moonrag.Document] = []
  for document in documents {
    for chunk in splitter.split(document) {
      pieces.push(chunk)
    }
  }
  let _ = indexer.index(pieces)

  let retriever : &@moonrag.Retriever = @moonrag.SimilarityRetriever::new(embedder, store)
  retriever.retrieve("who lives in London", limit=3)
}

The embedder is yours to write. HashingEmbedder is a deterministic stand-in that needs no network — good for tests and for getting the shape of a pipeline before a model is involved. With the examples' corpus and that embedder, the equivalent program prints:

03

Choose the splitter

Chunking decides what the library can find. Four rules, one per splitter: paragraphs with an overlap, a token budget you supply, headings with a path, or headings in HTML. For Markdown, the syntax tree is read, so a # inside a fence is a comment and a code block is never cut. 

let markdown = "# Install\n\nmoon add moonbitstack/moonrag.\n\n## Search\n\nBuild a store, then search.\n"
let splitter = @split.MarkdownSplitter::new(chunk_size=1000)
let chunks = splitter.split(@moonrag.Document::new(markdown))
assert_eq(chunks.length(), 2)
assert_eq(chunks[1].str_meta("h1"), Some("Install"))
assert_eq(chunks[1].str_meta("h2"), Some("Search"))

The heading text lands in the metadata under the key you chose, and every chunk carries the whole path down to it. A level you do not list does not split — it stays in the text of the section above: 

let splitter = @split.MarkdownSplitter::new(headings=[
  @split.MarkdownHeading::new(1, "h1"),
  @split.MarkdownHeading::new(2, "h2"),
])

Defaults: all six levels split, headings are stripped from the chunk, overlap is zero.

04

Put the vectors somewhere

InMemoryVectorStore is the reference implementation: documents in insertion order, every candidate scored on every search, filters applied before ranking. When the corpus has to outlive the process, the same contract is a table — and the database is chosen once, when the connection is opened. 

pub async fn[T : @moondb.AsyncDriver] search_with(
  driver : T,
  embedder : &@moonrag.Embedder,
) -> Array[@moonrag.Scored] raise {
  let store = @sql.SqlVectorStore::new(driver, embedder, dimension=256)
  store.create()
  let _ = store.add([@moonrag.Document::new("the harbour at dawn")])
  let query = embedder.embed(["the harbour"])[0]
  store.search(query[:], limit=3)
}

dimension is the width of the embedding model, fixed at construction because the column is declared with it. On PostgreSQL with pgvector the search is one statement; on SQLite the rows come back and the cosine is computed in this process. A SQLite driver that blocks goes in through BlockingDriver: 

let driver = @sql.BlockingDriver::new(@moonsqlite.SqliteDriver::open("app.db"))

This last line needs moon add moonbitstack/moonsqlite; the library itself depends on no driver.

05

Re-index without re-embedding

Embedding is the expensive part, so a second run over an unchanged corpus must embed nothing. The indexer keeps a content hash per stored id: 

let indexer = @index.Indexer::new(store)
let stats = indexer.index(chunks)                        // added / updated / skipped / deleted
let cleaned = indexer.index(chunks, cleanup=@index.Cleanup::Full)
unchanged
same id, same content hash: skipped, nothing embedded.
changed
same id, different text or metadata: the old copy is deleted, the new one added.
gone
Incremental deletes documents whose source appears in this run and whose id does not; Full deletes everything this run did not produce; None deletes nothing.

The source key defaults to source, the metadata key every loader writes. Moving a file changes the source but not the hash, so a moved file is not re-embedded.

When it goes wrong

what you see what it means
Mismatch a vector met one of another width; the store and the model disagree
Empty a blank id, a blank heading key, a budget that is not positive
Exceeded an overlap larger than the budget, or two headings at one level
a filter that returns nothing a missing key matches nothing — except under Not, which matches what the inner filter would have failed
the same passage five times near-duplicates winning a plain search; rerank with MMR
